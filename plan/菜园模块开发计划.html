班级共享菜园
互动管理模块

在现有阅读记录小程序中新增菜园子模块，让全班家长和孩子共同维护一个虚拟+现实结合的班级菜园，通过任务领取、健康值维护、成长相册打造班级凝聚力。

🏗️基于 微信云开发
📦新增 4个集合
☁️新增 8个云函数
📱新增 4个页面
🗓️预计 3期开发，约3周
📋
项目概览
核心设计决策与技术背景
游戏化机制
班级共同体
菜园有一个整体「健康值」，全班孩子共同维护，任务没人认领健康值下降，大家都完成则进入繁荣状态
任务颗粒度
班级任务
「本周班级需要浇水2次」，家长自愿认领，每个任务可多个家庭认领，体现共享精神
完成核实
家长拍照
家长完成任务后上传1~3张照片，管理员（老师/班委）轻量审核，通过后自动加健康值
任务频率
每周3~5个
系统按种植周期预设任务，管理员后台可随时调整增删，固定必选任务+选做任务

cloudfunctions/garden/getTasks/
新增
获取本周任务列表，包含每个任务的认领状态和当前用户是否已认领。任务大厅和主页卡片均调用此接口。
入参：{ week_no? } | 出参：{ tasks: [...], user_claimed_ids: [...] }
P1
garden/claimTask
cloudfunctions/garden/claimTask/
新增
认领任务。需校验：任务是否存在、是否已过期、用户是否已认领过同一任务。认领成功后在 task_records 创建记录（status: claimed）。
入参：{ task_id } | 出参：{ success, record_id }
P1
garden/submitTask
cloudfunctions/garden/submitTask/
新增
提交任务完成。上传照片后调用此接口，将 task_records 状态改为 submitted，通知管理员审核。照片通过 wx.cloud.uploadFile 上传到云存储，此处只接收 URL 数组。
入参：{ record_id, photos: [url], note? } | 出参：{ success }
P1
garden/approveTask
cloudfunctions/garden/approveTask/
新增
管理员审核任务。通过时：更新 task_records 状态为 approved，将任务对应的 health_value 加到 garden_config.health_point（不超过100），将 points_reward 加到用户积分，同步照片到 garden_photos。驳回时：状态改为 rejected。需调用 checkAdmin 验证权限。
入参：{ record_id, action: 'approve'|'reject', reason? } | 出参：{ success, new_health }
P1
garden/updateConfig
cloudfunctions/garden/updateConfig/

管理员更新菜园状态（阶段、描述、配图、手动调整健康值等）。管理后台调用。需验证 admin 权限。
入参：{ health_point?, current_stage?, stage_desc?, stage_image?, week_no? } | 出参：{ success }

审核流程（approveTask 云函数核心逻辑）
cloudfunctions/garden/approveTask/index.js — 核心逻辑 JavaScript
// 审核通过时的完整流程 if (action === 'approve') { // 1. 更新 task_records 状态 await db.collection('task_records').doc(record_id).update({ data: { status: 'approved', approved_at: db.serverDate(), approved_by: OPENID } }) // 2. 获取任务的 health_value 和 points_reward const task = await db.collection('garden_tasks').doc(record.task_id).get() // 3. 更新菜园健康值（不超过100） const config = await db.collection('garden_config').limit(1).get() const newHealth = Math.min(100, config.data[0].health_point + task.data.health_value) await db.collection('garden_config').doc(config.data[0]._id).update({ data: { health_point: newHealth, last_updated: db.serverDate() } }) // 4. 更新用户积分 await db.collection('users').where({ openid: record.openid }).update({ data: { points: db.command.inc(task.data.points_reward) } }) // 5. 同步照片到 garden_photos（如果有照片） if (record.photos && record.photos.length > 0) { for (const url of record.photos) { await db.collection('garden_photos').add({ data: { image_url: url, uploader_openid: record.openid, child_name: record.child_name, week_no: currentWeek, source: 'task', taken_at: db.serverDate() } }) } } }

开发注意事项
踩坑预警，参考现有项目经验
🚨
云函数部署必须先在控制台手动创建：每个新云函数（garden/getStatus、garden/getTasks等）都必须先在微信云开发控制台创建空函数，再通过开发者工具上传代码。跳过这步会导致部署失败。
⚠️
数据库单次查询20条限制：已在现有代码中有批量查询方案（pages/list/list.js），任务记录查询如果超过20条需要分页。初期30个家庭任务量不大，可以先不处理，后期再加分页。
⚠️
garden_config 只有1条记录：不要用 add，要用 update。第一次初始化时手动在云控制台插入一条记录，之后代码始终用 doc(id).update() 更新。建议把这条记录的 _id 写在注释里备查。
ℹ️
照片上传流程：照片不经过云函数，直接在小程序端调用 wx.cloud.uploadFile() 上传到云存储，获得 fileID 后再把 fileID 数组传给 submitTask 云函数存入数据库。fileID 格式：cloud://env-id.xxx/garden/photos/filename.jpg。
ℹ️
OpenID 大小写：现有代码已有记录，cloud.getWXContext().OPENID 的大小写可能不一致，比较时统一用 .toLowerCase()。
💡
先用手动方式替代自动化：第一期不需要自动衰减、不需要自动推送，管理员手动调整健康值完全够用。把复杂的自动化逻辑放到第三期，先把核心流程跑通。
